# 用户故事地图生成工作流

## 概览

工作流分为两大阶段，**逐个能力迭代推进**，所有能力地图完成后才生成总览：

```
Phase 1: 逐个能力生成地图（循环 N 次）
  对每个能力：
    读取 -> 自我分析 -> 提问（如需） -> 出方案 -> 用户确认 -> 立即落盘 -> 下一个能力

Phase 2: 生成总览（1 次）
  读取全部已落盘能力地图 -> 自我分析 -> 提问（如需） -> 出方案 -> 用户确认 -> 落盘
```

### 流程定位机制

agent 本身不持有跨轮状态。每次被委派时，通过**扫描产品库 `用户故事地图/` 目录中已存在的地图文件**来判断当前应该处理哪个能力或是否进入总览阶段：

1. 扫描产品库全部能力文档，得到能力清单（有序）。
2. 扫描 `用户故事地图/` 目录，得到已落盘的地图文件清单。
3. 对比两个清单：
   - 如果有能力还没有地图文件 -> 处理下一个未完成的能力。
   - 如果所有能力都有地图文件但没有总览 -> 生成总览。
   - 如果总览也存在 -> 返回完成状态。

---

## Phase 1: 逐个能力生成地图

对每个能力执行以下循环。一个能力完成后（地图已落盘），在下一轮委派中自动进入下一个能力。

### Step 1-CAP: 读取能力输入

#### 目标

读取当前能力的文档和用户故事，提取构建地图所需的事实数据。

#### 执行步骤

1. 扫描产品库 `用户故事地图/` 目录，对比能力清单，确定当前要处理的能力（第一个还没有地图文件的能力）。
2. 读取该能力的文档（`*-能力文档.md`），提取：能力名称、能力描述、用户角色、业务场景、业务流程、优先级。
3. 读取该能力下的全部用户故事文件（`*-UserStory/*故事.md`），提取：故事标题、故事描述、角色、优先级、所属能力。
4. 读取设计文档（`productArchitectureDesignPath`），提取与该能力相关的产品角色和核心场景。

#### 输出

- 当前能力的信息清单（能力名称、业务流程、用户角色）
- 该能力下的故事清单（标题、描述、角色、优先级）

#### 质量门

- 能力文档必须存在且可读。
- 该能力下至少有 1 个用户故事文件。
- 如果故事文件缺少优先级信息，标记为"待确认"。

---

### Step 2-CAP: 自我分析与提问

#### 目标

基于读取到的能力文档和故事信息，**自我分析是否存在不确定的地方**，如果有，向用户提问弄清楚。

#### 执行步骤

1. 基于能力文档的"业务流程"字段，尝试提取该能力的旅程节点（横轴）。
2. 基于故事文件的优先级和描述，尝试将故事映射到旅程节点 × 优先级的 2D 矩阵。
3. 尝试识别 P0 行走路径。
4. **自我检查以下不确定项**：

| 检查项 | 不确定时的处理 |
| --- | --- |
| 能力的业务流程是否清晰？旅程节点能否确定？ | 如果业务流程模糊或缺失，向用户提问该能力的核心操作流程是什么 |
| 每条故事的优先级（P0/P1/P2）是否明确？ | 如果故事文件没有优先级标注，向用户提问该故事的优先级 |
| 故事与旅程节点的归属是否清晰？ | 如果某条故事可能属于多个节点，向用户确认归属 |
| P0 故事是否构成连贯行走路径？ | 如果 P0 行有断裂，向用户确认是否需要补充或调整 |
| 是否有故事似乎不属于当前能力？ | 如果故事的能力归属可疑，向用户确认 |

5. 如果存在不确定项，**每轮只问一个问题**（按 `output-format.md` 格式），返回 `needs-input`。
6. 如果没有不确定项，直接进入 Step 3-CAP。

#### 输出

- 不确定项清单（如有）
- 向用户提出的问题（如有，每轮一个）

#### 用户确认点

如果存在问题，向用户展示问题并等待回答。用户回答后，主调度器重新委派，agent 继续分析或进入下一步。

---

### Step 3-CAP: 生成能力地图方案

#### 目标

为当前能力生成用户故事地图草稿方案，向用户展示并请求确认。

#### 执行步骤

1. 读取 `core-mechanisms.md`、`guides/story-placement.md`、`guides/walking-skeleton.md`。
2. 读取 `writing-paradigm/map-writing.md` 和 `templates/capability-map.md`。
3. 构建该能力的 2D 矩阵：
   - 列 = 能力内旅程节点（从业务流程提取，从左到右）
   - 行 = 优先级（P0 最上，P1 中间，P2 最下）
   - 单元格 = 故事卡片（完整形式）
4. 识别该能力的 MVP 行走路径，标注 ⭐。
5. 撰写能力级行走路径叙事。
6. 标注覆盖空白和路径断裂（如有）。
7. 按 `templates/capability-map.md` 结构生成完整草稿预览。
8. 返回 `map-draft-ready`（含 `target=capability-{能力名}`）。

#### 输出

- 能力级地图草稿（1 个文件预览）
- 行走路径叙事
- 覆盖空白清单（如有）

#### 用户确认点

展示能力级地图草稿预览，询问用户：
- 2D 矩阵布局是否合理？
- 故事归属是否准确？
- MVP 行走路径是否完整？
- 是否需要调整？

#### 质量门

- 地图必须包含 2D 矩阵表格（不是列表）。
- 不得使用 ASCII 字符画画流程图。
- 每条故事必须且只能放置在一个矩阵单元格中。
- wikilink 指向的故事文件必须与产品库中的实际文件名一致。
- MVP 行走路径必须高亮标注。

---

### Step 4-CAP: 落盘能力地图

#### 目标

用户确认后，**立即将能力地图写入产品库**，然后进入下一个能力。

#### 执行步骤

1. 读取 `persist-guide.md`。
2. 将已确认的地图内容写入 `<产品库>/用户故事地图/{产品名}-{能力名}-用户故事地图.md`。
3. 校验 wikilink 有效性。
4. 返回 `map-persisted`（含 `target=capability-{能力名}`）。
5. 主调度器重新委派后，agent 扫描已落盘文件，自动进入下一个能力（回到 Step 1-CAP）。

#### 质量门

- 只写入用户已确认的内容，不得重新改写。
- 文件编码 UTF-8，换行符 LF。
- 落盘后校验文件已成功写入。

---

## Phase 2: 生成总览

当所有能力的地图都已落盘后，进入总览生成阶段。

### Step 1-OV: 读取全部已落盘能力地图

#### 目标

读取已落盘的全部能力地图文件，作为总览的输入。

#### 执行步骤

1. 扫描 `用户故事地图/` 目录，确认所有能力地图文件已存在。
2. 逐个读取能力地图文件，提取：
   - 能力名称、旅程节点
   - 各优先级的故事清单
   - 行走路径故事（⭐ 标记的故事）
   - 跨能力关联信息
3. 读取设计文档，提取产品概述、全局用户角色、核心场景。

#### 输出

- 全部能力地图的汇总信息
- 产品概述信息

---

### Step 2-OV: 自我分析与提问

#### 目标

基于已落盘的能力地图，**自我分析生成总览是否存在不确定的地方**，如果有，向用户提问。

#### 执行步骤

1. 尝试从设计文档的核心场景推导全局旅程阶段（总览横轴）。
2. 尝试将各能力映射到全局旅程阶段。
3. 尝试构建总览 2D 矩阵（全局旅程阶段 × 优先级）。
4. 尝试识别全局 MVP 行走路径。
5. **自我检查以下不确定项**：

| 检查项 | 不确定时的处理 |
| --- | --- |
| 全局旅程阶段如何划分？ | 如果设计文档核心场景不足以推导，向用户提问 |
| 各能力如何映射到全局旅程阶段？ | 如果一个能力跨越多个阶段，向用户确认主要阶段 |
| 总览矩阵中各能力故事如何横向对齐？ | 如果能力间旅程节点颗粒度不一致，向用户确认对齐策略 |
| 全局 MVP 行走路径是否连贯？ | 如果跨能力路径有断裂，向用户确认 |

6. 如果存在不确定项，每轮只问一个问题，返回 `needs-input`。
7. 如果没有不确定项，直接进入 Step 3-OV。

---

### Step 3-OV: 生成总览方案

#### 目标

生成总览地图草稿方案，向用户展示并请求确认。

#### 执行步骤

1. 读取 `templates/overview-map.md`。
2. 构建总览内容：
   - 产品概述（从设计文档提取）
   - 全局用户旅程叙事线
   - 能力覆盖矩阵（能力 × 旅程阶段）
   - **2D 故事地图矩阵**（全局旅程阶段 × 优先级，紧凑形式故事卡片）
   - MVP 行走路径（跨能力的主干路径叙事）
   - 跨能力关联表
   - 能力索引（wikilink 到各能力级地图）
3. 返回 `map-draft-ready`（含 `target=overview`）。

#### 用户确认点

展示总览地图草稿预览，询问用户确认。

---

### Step 4-OV: 落盘总览

#### 目标

用户确认后，将总览写入产品库。

#### 执行步骤

1. 将已确认的总览内容写入 `<产品库>/用户故事地图/{产品名}-用户故事地图-总览.md`。
2. 返回 `map-persisted`（含 `target=overview`）。
3. 所有地图已完成，返回完成状态。

---
