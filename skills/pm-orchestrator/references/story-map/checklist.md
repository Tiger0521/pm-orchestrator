# 用户故事地图质量门

## 1. 矩阵形态检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 2D 矩阵存在 | 总览地图和每个能力级地图都包含至少一个 Markdown 表格形式的 2D 矩阵 | 阻止 persist，退回 generate 重新构建 |
| 横轴有方向 | 矩阵列标题按旅程阶段从左到右排列，有明确的时间/流程方向性 | 阻止 persist，重新确认旅程阶段排序 |
| 纵轴有层次 | 矩阵行按 P0 -> P1 -> P2 从上到下排列 | 阻止 persist，调整行顺序 |
| 非 ASCII 画图 | 旅程叙事线通过矩阵列标题和文字描述体现，不使用 ASCII 字符画画流程图 | 阻止 persist，移除 ASCII 图，改用表格 |

## 2. 行走路径检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 路径连贯 | P0 行的每个旅程阶段至少有一条故事（或明确标注"该阶段无需 MVP 覆盖"） | 标记"行走路径断裂"，向用户确认 |
| 路径标注 | 行走路径上的 P0 故事用 ⭐ 或加粗标注 | 补充标注 |
| 路径叙事 | 存在一段一句话以上的行走路径描述，说明用户如何从旅程起点到终点 | 补充叙事描述 |
| MVP 统计 | 存在 MVP 范围统计（故事数、阶段数、能力数） | 补充统计 |

## 3. 故事覆盖检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 全覆盖 | 产品库中全部用户故事都出现在地图中 | 补充遗漏故事 |
| 无重复 | 每条故事在总览地图中只出现一次 | 去重 |
| 优先级完整 | 每条故事都有明确的 P0/P1/P2 归属 | 向用户确认优先级 |
| 旅程归属 | 每条故事都映射到一个旅程阶段 | 向用户确认归属 |

## 4. 数据一致性检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 总分一致 | 总览地图故事总数 = 各能力级地图故事总数之和 | 修正计数差异 |
| 能力一致 | 总览索引表中的能力列表与实际能力级地图文件一致 | 修正索引 |
| 链接有效 | 总览地图中的 wikilink 指向的能力级地图文件实际存在 | 修正链接 |
| 故事链接 | 能力级地图中的 wikilink 指向的用户故事文件在产品库中实际存在 | 修正链接或标注为"规划中" |

## 5. 视觉规范检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 表格格式 | 2D 矩阵使用标准 Markdown 表格语法，列对齐 | 修正格式 |
| 卡片紧凑 | 总览矩阵单元格中的故事卡片使用紧凑形式（标题 + wikilink + 角色），不展开全部字段 | 压缩为紧凑形式 |
| 卡片完整 | 能力级矩阵中的故事卡片使用完整形式（全部要素） | 补充缺失字段 |
| 覆盖空白 | 空单元格标注"-"或"覆盖空白"，不留空 | 补充标注 |
| 颜色/标记 | 不同能力用不同的 emoji 或标签区分（可选） | 补充区分标记 |

## 6. 文件结构检查

| 检查项 | 通过条件 | 失败处理 |
| --- | --- | --- |
| 文件命名 | 总览文件命名 `{产品名}-用户故事地图-总览.md`；能力级文件命名 `{产品名}-{能力名}-用户故事地图.md` | 重命名 |
| Frontmatter | 每个文件含 `product`、`type: "指南"`、`tags`、`title` 字段 | 补充 frontmatter |
| 目录位置 | 全部地图文件位于产品库的 `用户故事地图/` 目录 | 移动到正确目录 |
| 无冗余 | 不重复维护故事列表（总览不复制各能力的故事详情，仅索引） | 移除重复内容 |
