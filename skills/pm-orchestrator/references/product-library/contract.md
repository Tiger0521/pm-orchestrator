# 产品库落盘契约

本文件只定义产品库定位、目录、命名、内容和脚本职责。产品匹配读取 `references/requirement-analysis/guides/product-matching.md`；实现细节由脚本承载。

## 1. 定位与身份

自动发现从终端当前目录开始查找固定容器 `product-library/`：检查当前目录；未找到时逐级向上，最多检查 3 个父目录。找到后，把其中包含唯一匹配 `^.+架构设计\.md$` 的根文档的一级子目录列为可用产品库；没有候选时只允许从 Git 仓库获取，或由用户提供已有产品库的本地路径。显式提供的路径不受自动发现容器限制。产品库不由本 Skill 创建；无论来源如何，都只以该正则和唯一性为准。

```text
<workspace-or-parent>/
└── product-library/
    ├── 网络资源中心产品库/网络资源中心产品库架构设计.md
    └── 运维监控产品库/运维监控产品库架构设计.md
```

匹配 `^.+架构设计\.md$` 的唯一文件是产品库根标识和最高产品设计标准。产品库目录名由提供方定义，使用中文且不得包含空格、路径分隔符或文件系统禁用字符。

## 2. 产品简称

- 产品目录使用产品全名，产品文件使用简称前缀。
- 产品全名使用 `简称：描述` 格式：2–6 个汉字的简称作前缀，全角冒号 `：` 分隔，冒号后是描述部分（汉字）。半角冒号 `:` 是 Windows 文件系统禁用字符，必须用全角 `：`。
- 简称由产品负责人定义，必须是 2–6 个汉字，在同一产品库内唯一，且必须等于产品全名中冒号前的部分。
- 全名与简称登记在匹配根文档的产品矩阵区域后才允许创建产品目录。

产品矩阵使用 HTML 注释标记区域，每个产品对应一个 `## 产品全名` 标题和一个 `<!-- product:产品全名:start/end -->` 标记块：

```markdown
<!-- product-matrix:start -->
## 网资：网络资源全生命周期管理

产品概述（导出时从 Epic 产品定位提取，之后手动维护）...

<!-- product:网资：网络资源全生命周期管理:start -->
**简称**：网资

### 能力索引

#### 设备领用能力
- [[网资-设备领用能力-能力文档|设备领用能力]]

### 故事索引

#### 设备领用能力
- [[网资-设备领用能力-提交领用申请故事|提交领用申请]]

<!-- product:网资：网络资源全生命周期管理:end -->
<!-- product-matrix:end -->
```

标记块内由脚本自动维护简称、能力索引和故事索引；标记块外的标题和概述由用户手动维护，首次导出时由脚本从 Epic 产品定位提取。能力索引和故事索引按父能力分组（`#### 父能力名`），叶子能力以自身名分组。

## 3. 目录结构

```text
product-library/<产品库名称>/
├── <匹配 ^.+架构设计\.md$ 的根文档>
└── <产品全名>/
    ├── <简称>-需求卡片.md
    ├── <简称>-设计文档.md
    ├── <叶子能力>/
    │   ├── <简称>-<叶子能力>-能力文档.md
    │   └── UserStory/<简称>-<叶子能力>-<故事标题>故事.md
    └── <父能力>/
        └── <子能力>/
            ├── <简称>-<父能力>-<子能力>-能力文档.md
            └── UserStory/<简称>-<父能力>-<子能力>-<故事标题>故事.md
```

能力目录必须以“能力”结尾。导出脚本会对过程文档中的每一级能力名自动补齐“能力”后缀，不改写过程文档标题；补齐后出现同一能力路径的多个 Feature 时阻断导出。叶子能力放 1 份能力文档和 `UserStory/`，不能有子能力；父能力只放一个或多个子能力目录，不能放能力文档或 `UserStory/`。当前契约只允许一层父能力和一层子能力。

## 4. 命名

产品全名（目录名）用中文加全角冒号 `：`（见第 2 节）；能力目录名和文件名用中文加半角中划线 `-`。半角冒号 `:` 属 Windows 文件系统禁用字符，须用全角 `：`。所有名称不得包含空格、路径分隔符或其他文件系统禁用字符。

- 需求卡片：`简称-需求卡片.md`
- Epic 设计文档：`简称-设计文档.md`
- 顶层叶子能力文档：`简称-能力-能力文档.md`
- 子能力文档：`简称-父能力-子能力-能力文档.md`
- 顶层叶子能力故事：`简称-能力-故事标题故事.md`
- 子能力故事：`简称-父能力-子能力-故事标题故事.md`
- 根标识：唯一匹配 `^.+架构设计\.md$` 的根文档

用户故事文件名使用“故事标题故事”后缀，不使用序号；标题仅可包含中文、英文字母、数字和单个中划线。导出时会将同一能力下、标题匹配的旧序号或旧无后缀文件改名为新文件名；若故事标题重复，则阻断导出。

## 5. Frontmatter

除匹配正则的产品库根文档外，每份 Markdown 必须包含 `product`、`type`、`aliases` 和 `tags`；能力文档和用户故事还必须包含 `capability`。

```yaml
---
product: 网络资源全生命周期管理
type: 能力文档
capability: 设备领用能力/领用审批能力
aliases:
  - 设备领用能力/领用审批能力
tags:
  - 网资
  - 能力文档
  - 设备管理能力/领用审批能力
---
```

`type` 只允许 `需求卡片 | 设计文档 | 能力文档 | 用户故事`。`capability` 使用相对于产品目录的能力路径，不包含产品目录名。`aliases` 和 `tags` 均为 YAML 列表，由导出脚本自动注入。产品库不得保留过程空间的 `id`、`projectId`、`refs` 或 `status`。导出时必须把正文和保留 frontmatter 中的过程 ID 全量转换为产品库文件名或可读名称：Wiki 链接（含显示文本、章节/块锚点和路径形式）及 Markdown 链接指向已导出文档时改为产品库 Wiki 链接；指向未导出过程文档时降级为显示文本或 `refs.json` 中的文档标题；任何无法映射的过程 ID 都必须阻止导出。校验脚本会拒绝仍含过程 ID 的产品库。

`aliases` 和 `tags` 的取值规则：

| 文档类型 | aliases | tags |
| --- | --- | --- |
| 需求卡片 | `[产品全名]` | `[简称, 需求卡片]` |
| 设计文档 | `[产品全名]` | `[简称, 设计文档]` |
| 能力文档 | `[能力路径]` | `[简称, 能力文档, 能力路径]` |
| 用户故事 | `[能力路径 故事标题]` | `[简称, 用户故事, 能力路径]` |

`tags` 中的能力路径使用 `/` 分隔（如 `设备管理能力/领用审批能力`），在 Obsidian 中形成嵌套标签。`aliases` 中的能力路径同样使用 `/` 分隔。

## 6. 文档映射与 Obsidian

- 需求卡片映射为 `简称-需求卡片.md`。
- Epic 映射为 `简称-设计文档.md`，并承担产品概览职能。
- Feature 映射为对应叶子能力的能力文档。
- User Story 和 GWT 映射到对应叶子能力的 `UserStory/`。
- 使用 `[[文件名]]` 或 `[[文件名|显示文本]]` 建立链接，不写扩展名；同名历史文件使用带路径链接兜底。
- 导出脚本自动注入 `aliases` 和 `tags`；`product` 字段用于搜索和图谱分组，`tags` 用于标签过滤，`aliases` 用于别名链接。
- 校验脚本检测全库同名文件和别名冲突。

项目工作区是过程空间；产品库是用户选择从阶段文档完整的过程项目导出的正式只读资产。需求分析阶段的需求卡片、Epic 和能力清单中的全部 Feature 均已写入过程项目后，主调度器必须询问是否导出到产品库目标目录；用户选择导出时，先预览变更并再次确认后才执行。正常阶段的 `mode=persist` 不得直接写产品库。产品库导出是需求分析阶段的收尾动作，不阻塞后续 Story 拆解：用户暂不导出时需求分析仍可结束并进入下一阶段，只需保留“产品库待导出”状态。

## 7. 脚本职责

- `acquire-product-library.sh`：从 Git 仓库克隆或更新产品库，或规范化用户提供的已有本地产品库路径；不创建空产品库、不复制本地库、不执行 `git init`。
- `validate-product-library.sh`：定位或校验目录、简称、命名、frontmatter（含 `aliases`/`tags` 格式）、层级、文件名唯一性、别名冲突和链接完整性。
- `export-to-library.sh`：读取 `refs.json` 和正式产物，转换名称与 frontmatter（注入 `aliases`/`tags`），预览后增量写入并更新产品矩阵标记区域。
- `rename-product.sh`：预览简称变更，确认后批量改名、更新链接和产品矩阵标记区域，失败时回滚。

导出和改简称默认只预览；只有用户确认后才使用 `--apply`。导出时新文件创建、变化文件覆盖、相同文件跳过；项目已不再导出但产品库仍存在的文件标记为 `STALE` 并保留，不自动删除，能力数和用户故事数在处置前仍包含这些文件。写入后必须校验。简称变更前校验格式与唯一性，`product` 始终保存产品全名。
