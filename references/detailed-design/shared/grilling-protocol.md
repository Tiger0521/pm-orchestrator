# Grilling 问答协议（Step 1-4 通用）

本文件定义详细设计四个 Step 的 grilling 问答方法。借鉴需求分析阶段的追问风格：有建设性地逐轮敲定设计决策，不为了问而问，也不替用户做裁决。

**职责边界**：本文件只管"问什么、何时问、何时停"。每轮一问、理解回执、选项格式等通用交互协议见 `confirmation-method.md`；各步执行流程见对应 step 文件夹的 `workflow.md`。

---

## 1. 核心口径：选择性 grilling

- **决策域必问**：不能从上游文档机械推导、存在多种实质不同的合理方案、选错会传导到下游的取舍点。不问就是越权。
- **推导域禁问**：能从上游文档、已确认决策或固定规则机械推导的内容。问了就是失职——用户会从"做决策"退化成"人肉校对"。
- 判定准则：把该内容的全部上游输入摆在一起，是否只剩一种合理答案？是 → 推导域，直接生成；否 → 决策域，先问再写。

## 2. 事实先查，决策再问

每次提问前按以下顺序处理：

1. 先读取 Story、Feature、溯源矩阵、产品库用户故事地图、`productArchitectureDesignPath` 根文档、已确认的下游产物，把能推导的先推导出来。
2. 提问时必须携带推导依据：`根据故事地图的 P0 主干（登录→领用申请→审批），建议一级导航为"工作台/设备管理/审批中心"，是否调整？`
3. agent 给建议和依据，最终裁决者是用户。

## 3. 各步决策域清单（必问）

### 3.1 Step 1：功能架构与动线规划

**Phase 1（核心页面层级与系统边界）**

| 问题域 | 敲定内容 | 收敛标志 |
| --- | --- | --- |
| 页面层级草案 | 一级导航分组、二级页面清单、层级依据 | 用户确认层级结构 |
| 多端/多角色拆分 | 是否区分用户端/管理端/审批端，各端页面集 | 用户确认拆分方案 |
| 系统边界 | 明确包含的页面/模块、明确排除的模块和外部系统 | 用户确认包含/不包含清单 |
| 功能线业务动线 | 系统分几条功能线、每条线从入口到完成的步骤与覆盖 Story（基于故事地图旅程与 Story 分组推导，Story 并集须覆盖全部 Story） | 用户确认功能线清单与各线动线 |

**Phase 2（页面映射）**

| 问题域 | 敲定内容 | 收敛标志 |
| --- | --- | --- |
| Story 归属歧义 | 一条 Story 归哪个页面（提供选择题） | 每条歧义 Story 有用户裁决 |
| 弹窗 vs 独立页面 | 交互承载形式的取舍 | 每个歧义点有用户裁决 |
| 入口与出口 | 每个页面从哪来、到哪去 | 用户确认关键入口出口 |
| 跳转闭环 | 孤儿页面检查、断链检查 | 无孤儿页面、无断链 |

### 3.2 Step 2：原型设计与规范对齐

| 问题域 | 敲定内容 | 收敛标志 |
| --- | --- | --- |
| 目标平台 | Web Dashboard / Web Landing / Web App / Mobile App / Mini Program / Admin Backend（六选一，平台说明见 `../step2-原型设计与规范对齐/ui-design-style.md` 第 3.1 节） | 用户选定平台 |
| UI 风格预设 | 平台 x 风格矩阵（5 个最匹配候选 + 补充描述，见 `../step2-原型设计与规范对齐/ui-design-style.md` 第 3.4 节） | 用户选定预设 |
| 核心页面布局模式 | 每类核心页面的布局取舍用方案对比题裁决：列表页（表格 vs 卡片）、详情页（标签页 vs 长页滚动）、表单承载（弹窗 vs 独立页 vs 分步向导） | 每类核心页面模式有用户裁决 |
| 组件复用范围 | 跨页面同模式交互是否统一抽公共组件（如所有列表页共用筛选器） | 复用清单有用户裁决 |
| 布局与层级冲突 | 原型布局需偏离 Step 1 已确认页面层级时（无冲突则不问） | 冲突点有用户裁决 |

### 3.3 Step 3：交互规则与边界补全

| 问题域 | 敲定内容 | 收敛标志 |
| --- | --- | --- |
| 状态机关键流转 | 状态集有歧义时的取舍、非法流转的拦截方式、终态定义（如"已废弃"能否恢复） | 关键流转有用户裁决 |
| 高风险兜底策略 | 用方案对比题裁决：并发冲突（提示刷新 vs 锁定编辑）、未保存离开（自动存草稿 vs 确认弹窗）、失败重试（自动 vs 手动） | 每个高风险交互有用户裁决 |
| 校验归属 | 前端/后端/双端校验，仅在双端行为实质不同时问 | 歧义点有用户裁决 |
| 未编号规则 | Feature 文档中未编号的规则是否有效、编号归属（BR-TBD 项） | 每项有用户裁决 |
| 异常适用性歧义 | 某异常在该 Story 的 GWT 验收标准中是否可能发生 | 歧义项有用户裁决 |

### 3.4 Step 4：Sprint 分解

| 问题域 | 敲定内容 | 收敛标志 |
| --- | --- | --- |
| 团队产能与 Sprint 长度 | 人天/周期口径（选择题） | 用户给定产能口径 |
| 风险容忍度 | 高风险 Story 前置（先啃硬骨头）还是后置（先交付确定价值） | 用户裁决 |
| 首 Sprint 目标口径 | 一句话交付目标（agent 给建议，用户裁决） | 目标有用户确认 |
| 依赖排序歧义 | 依赖关系不明确时的排序裁决（依赖明确则不问） | 歧义点有用户裁决 |

### 4.2 Step 2

| 推导域 | 来源 | 处理方式 |

## 5. 层级边界：不问什么

每步只盘问本步决策域。越界内容记入 `forced_skips` 或 tracking 项：

| 归属 | 处理方式 |
| --- | --- |
| 其他 Step 的决策域 | 禁止盘问，留待对应 Step |
| 技术实现（接口设计、数据模型、技术选型） | 禁止盘问，属于下游技术设计 |
| 上游事实（Story 内容、Feature 规则、优先级） | 从上游读取，缺失时返回 `needs-input` |
| 本步推导域 | 直接推导生成，不问（见第 4 节） |

判定准则：如果这个内容不影响本步任何决策域的取舍，它就不该在本步问。

## 6. 收敛判据

**收敛前禁止生成草案**：grilling 未收敛就写文件，等于把未确认的假设写成事实；用户会花时间改一份本不该存在的初稿。

| 步骤 | 收敛判据（满足后才生成该步产物） |
| --- | --- |
| Step 1 Phase 1 | 页面层级、系统边界、功能线动线三块均有用户确认的结论，且无未裁决的层级/边界/功能线歧义 |
| Step 1 Phase 2 | 每条 Story 有归属页面（歧义 Story 均已裁决）、无孤儿页面、页面层级与业务流文档一致 |
| Step 2 | 风格预设、核心页面布局模式均有用户裁决（原型生成方式固定为交互式 HTML，无需裁决；组件复用无歧义时由 agent 建议、随草案确认） |
| Step 3 | 状态机关键流转、高风险兜底策略均有用户裁决，未编号规则处理完毕 |
| Step 4 | 产能口径、风险容忍度、首 Sprint 目标均有用户裁决 |

## 7. 常见偏差（必须避免）

- **不问事实**：问"系统里有哪些 Story"是失职——先读上游和故事地图。
- **拿推导域凑问题**：把能机械推导的内容包装成问题，是选择性 grilling 的头号偏差——用户被迫人肉校对。
- **一次问多个问题**：每轮只问一个，遵守通用交互协议。
- **替用户裁决**：agent 给建议和依据，最终裁决者是用户。
- **为凑问题而问**：所有问题都能从文档推导时，直接进入产物生成，不硬造问题。
- **grilling 与产物顺序颠倒**：先问完、收敛，再生成文件/草案；不是先生成再围着产物问。
- **用户确认口径漂移**：只有用户明确说"没问题/确认/可以"才算确认；"先看看""稍等"不算。
