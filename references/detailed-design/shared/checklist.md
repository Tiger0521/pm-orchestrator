# 详细设计阶段质量门

本文件是详细设计阶段（`detailed-design`）质量门校验的**唯一来源**。`mode=validate` 时加载本文件，逐项检查已有产物是否满足以下九类校验。

**校验依据**：

- 字段与 Frontmatter 校验依据 `output-contract.md`
- 写作质量校验依据 `design-writing.md` 与 `../step1-功能架构与动线规划/business-flow-writing.md`、`../step1-功能架构与动线规划/page-mapping.md`
- 决策域裁决校验依据 `grilling-protocol.md` 第 3 节（各步必问决策域）

**使用规则**：

- 本文件仅在 `mode=validate` 时加载，`mode=draft` 和 `mode=persist` 不预读
- 所有检查项均使用 checkbox 格式，逐条标记通过/未通过
- 任一项未通过即返回 `validation-failed`，不得跳过或忽略

每份文档包含 `id`、`product`、`type`、`aliases`、`tags`（产品库 frontmatter）。引用关系在 `refs.json` 中注册。

- [ ] 业务流的 `type` 为 `业务流`，ID 为 `<简称>-DF-FLOW<nn>`

## 3. 结构与流程质量（Step 1）

- [ ] 业务流文档包含核心页面层级、系统边界、业务动线、业务流程图四个章节
- [ ] 系统边界已定义（包含与不包含均写明，不包含带排除原因）
- [ ] 业务动线按功能线组织：每条功能线从入口到完成完整闭环、标注优先级与覆盖 Story，页面跳转用【】标注，功能线 Story 并集覆盖全部 User Story
- [ ] 业务流程图只含用户操作与页面动线，不涉及底层技术实现
- [ ] 页面映射表清晰，每条 Story 归属到页面（四列表格规范）
- [ ] 跳转闭环检查有结论（无孤儿页面、无断链）
- [ ] 两张 HTML 图为自包含单文件（无 CDN、外链字体、外链脚本）
- [ ] 两张 HTML 图与两份 md 文档零丢失一致：流程图每条功能线一条泳道、md 每个动线步骤有对应节点、节点常显 Story ID 且覆盖度 100%（页面名、层级、动线一致）
- [ ] 业务流与页面映射文档的页面名称一致
