# 规模自适应

本文件定义详细设计阶段按 `projectType` 区分的流程深度差异和产品库直启特殊路由。仅在确定流程深度时读取。

**职责边界**：本文件只管规模自适应。各 Step 执行流程见对应 step 文件夹的 `workflow.md`。

---

## 1. 项目类型识别

项目类型在需求分析 intake 中收敛，写入 `progress.json` 的 `projectType` 字段。详细设计阶段读取该字段决定流程深度。

| 类型 | 识别信号 | projectType 值 |
| ---- | -------- | -------------- |
| 全新项目 | 无现有设计文档；User Story 全部新增 | `new` |
| 迭代项目 | 已有设计文档；新增 User Story 需要设计 | `iteration` |
| 重构项目 | User Story 不变；需求聚焦性能/架构/技术栈变化 | `refactor` |

## 2. 流程差异

不同项目类型在各环节的流程深度不同：

| 环节 | 全新项目 | 迭代项目 | 重构项目 |
| ---- | -------- | -------- | -------- |
| 上游读取 | 读取全部 User Story + 溯源矩阵 + 用户故事地图 + 业务文档 | 读取新增 User Story + 关联 Feature + 业务文档 | 读取全部 User Story + 已有设计文档 + 业务文档 |
| Step 1 功能架构与动线规划 | 完整执行三阶段，新建业务流与页面映射文档 | 以已有业务流/页面映射为基线原地更新（沿用 ID），聚焦新增 Story 的层级扩展和归属增量；HTML 图按全量内容重新生成 | 保持已有页面映射不变，只产出受影响部分的变更说明 |
| Step 2 原型设计 | 全部页面生成原型（完整设计契约 + 全套内联标注） | 按变更规模分两档：**新模块**=完整设计契约 + office-hours 结构 + 全套内联标注；**小优化**（加字段/改文案/调样式）=只更新原型 HTML + 对应标注卡，不堆长文 | 只产出受影响页面的修改设计 |
| Step 3 交互契约 | 全部核心交互编写契约 | 聚焦新交互编写契约 | 只产出非功能性变更的契约 |
| Step 3 规则摘要 | 完整汇总全部规则 | 在已有规则上补充新增规则 | 聚焦重构引入的新约束 |

Sprint 分解已独立为 `sprint-planning` 阶段（`sprint-planner` 承接），不在本表范围内；其规模自适应见 `references/sprint-planning/workflow.md` 第 8 节。

`refactor` 项目与 `new`/`iteration` 项目在设计阶段的区别：refactor 保持已有设计不变，只产出非功能性设计变更（性能、安全、兼容性等）。subagent 读取 `productLibraryDocsPath` 下已有设计文档作为只读基线，不修改已有原型和交互契约。

**Step 2 变更规模信号（change-scope）**：`projectType=iteration` 时，Step 2 的产出深浅由 change-scope 信号决定。信号从上游 handoff 和用户本轮描述里自动推断：用户说"加个手机号字段"判为小优化；说"做一个会员中心"判为新模块。推断为小优化时在草案中显式标注"按小优化处理，如需完整流程说明请说明"，把纠错权交给用户。

## 3. 产品库直启的特殊路由

当 handoff 含 `sourceProduct` 时，这是从产品库直启的详细设计项目。subagent 按以下特殊路由执行：

- **只读上游**：先读取该产品的已有 Story、设计和能力文档（含 `用户故事地图/`，如存在）作为只读上游，再按本阶段流程设计
- **不得要求本地 User Story**：本地不存在 User Story，来源产品的文档作为只读上游
- **不得复制产品库文档**：不把产品库文档复制到当前过程项目
- **已有文档只读，新设计照常落产品库**：来源产品的已有文档（Story、设计、能力文档）不得修改或删除；新设计产物与常规项目一致直接落盘产品库来源产品目录（Step 1 直写 `详细设计/结构与流程图/`，Step 2-3 走 `render-doc.sh` 写入 `详细设计/` 各子目录），**不以过程项目作为设计产物的中间落点**；在回执和正式产物中保留来源产品 ID 与来源文档路径
- **定稿与常规项目一致**：refs 注册、记忆更新、校验按 `persist-guide.md` 正常执行

只读来源产品路由的完整定义见 `instruction.md` 的"只读来源产品路由"章节；Step 1 细节见 `../step1-功能架构与动线规划/workflow.md` 第 7 节。
