# Step 3 工作流：交互规则与边界补全

本文件是 Step 3 的唯一执行流程与核心机制。穷举异常分支，生成标准化的 GWT 交互文案，输出交互契约和规则摘要。

**职责边界**：本文件只管 Step 3 执行流程与机制。grilling 决策域与推导域见 `../shared/grilling-protocol.md` 第 3.3/4.3 节；GWT 写作规范（好差对比）见 `../shared/design-writing.md`；确认方法见 `../shared/confirmation-method.md`；产出字段见 `../shared/output-contract.md`；落盘步骤见 `../shared/persist-guide.md`。

---

## 1. 前置依赖（硬门禁）

- Step 2 的原型方案必须已用户确认，否则不得进入本步
- 读取已确认的 Step 1-2 产出：页面映射表（交互的附着页面）、原型文档（布局、元素、异常状态）
- 前置不满足时返回 `needs-input`

---

## 2. 执行步骤

1. 针对每个核心交互，按第 4 节异常穷举清单枚举异常分支（推导域，机械展开，见 `../shared/grilling-protocol.md` 第 4.3 节）
2. 判断每个异常场景是否在 User Story 的 GWT 验收标准中可能发生；不可能发生的跳过并说明理由（跳过规则见第 4 节），存在歧义的记入决策点清单
3. **grilling 敲定决策域**：按 `../shared/grilling-protocol.md` 第 3.3 节逐轮敲定，每轮一问，收敛判据见协议第 6 节：
   - 状态机关键流转：状态集歧义、非法流转拦截方式、终态定义（如"已废弃"能否恢复）
   - 高风险兜底策略：并发冲突、未保存离开、失败重试等用方案对比题裁决
   - 校验归属：前端/后端/双端，仅双端行为实质不同时问
   - 未编号规则：Feature 文档中未编号规则是否有效（BR-TBD 项）
   - 异常适用性歧义：枚举中记入决策点清单的项
4. 为每个异常生成标准化的 GWT 交互文案（从已裁决的兜底策略推导，写作规范见 `../shared/design-writing.md` 第 1 节）：

   ```
   Given [前置状态]
   When [触发动作]
   Then [系统行为]
   ```

5. 生成状态机描述（文字或 Mermaid，必备要素见第 5 节）
6. 生成交互规则表（触发 / 校验 / 流转 / 兜底四列，写作规范见 `../shared/design-writing.md` 第 2 节）
7. 生成错误提示文案表（错误场景 -> 提示文案，写作规范见 `../shared/design-writing.md` 第 3 节）
8. 从 Feature 文档提取规则编号和摘要，按第 6 节规则摘要机制生成规则摘要文档
9. 执行设计自检（见 `../shared/design-review.md`）
10. 输出交互契约草案 + 规则摘要草案（结构化草稿数据块，格式见 `../shared/output-contract.md` 第 4 节）

---

## 3. 如何询问

- 异常枚举先于 grilling：枚举是推导域，机械展开不问；枚举过程中浮现的歧义记入决策点清单，随后按 `../shared/grilling-protocol.md` 第 3.3 节逐轮敲定，每轮一问
- GWT 文案、错误提示文案、规则摘要从已裁决结论推导，不问（见协议第 4.3 节）
- 高风险兜底策略有歧义时，提供方案对比选择题：

```
退款提交失败时的异常处理方案：

A. 保留弹窗并展示错误信息 -- 用户可修正后重新提交
B. 关闭弹窗并跳转错误页面 -- 统一错误处理
补充描述：我自己填写
强制跳过：这个问题暂时不回答，记录为待验证并继续
```

## 4. 异常穷举机制

异常是设计真正考验的地方。对每个核心交互，至少考虑以下异常场景：

| 类型 | 说明 | 示例 |
| ---- | ---- | ---- |
| 触发条件异常 | 用户在错误时机操作 | 未保存就关闭页面、权限不足时点击操作按钮 |
| 输入校验异常 | 必填、格式、范围、重复 | 表单提交时名称为空、金额超出限制、邮箱格式错误 |
| 状态流转异常 | 非法跳转、并发冲突 | 已完成订单再次发货、两人同时编辑同一条配置 |
| 服务端返回异常 | 超时、500、断网 | 提交请求后服务端 500、网络断开、请求超时 |
| 兜底策略 | 每个异常都有对应的用户体验方案 | 网络异常时保留表单内容并提示重试、并发冲突时提示刷新 |

**异常穷举清单**：权限不足 / 数据为空/超限 / 网络异常/超时 / 并发冲突 / 重复提交 / 输入格式错误 / 非法状态跳转。

**跳过规则**：枚举不是机械遍历。如果某个异常场景在该 User Story 的 GWT 验收标准中不可能发生（如内部工具无网络场景），可以跳过但需说明理由。异常穷举的素材来源是 User Story 的 GWT 验收标准中已有的异常路径，subagent 在此基础上补充交互层面的异常。

## 5. 交互契约要素

交互契约是开发和测试的依据：

| 要素 | 说明 | 格式 |
| ---- | ---- | ---- |
| 状态机 | 用文字或 Mermaid 描述页面/对象的状态和流转 | `[状态A] -- 触发条件 --> [状态B]` |
| 交互规则表 | 触发 / 校验 / 流转 / 兜底四列 | 表格形式，每行一个交互规则 |
| API 调用约定 | 如有，列出接口、方法、入参、出参 | 表格形式 |
| 错误码和提示文案 | 每个错误场景对应一句话术 | 表格形式，错误场景 -> 提示文案 |

**交互规则表中的 GWT 格式**：借鉴需求拆解阶段的 GWT 验收标准格式，交互契约中的异常兜底列采用 GWT。User Story 的 GWT 验收标准定义"用户做什么，系统应该返回什么"，交互契约的 GWT 定义"在什么状态下，触发什么动作，系统怎么兜底"。两者互补：User Story GWT 是验收口径，交互契约 GWT 是实现口径。

---

## 6. 规则摘要机制

规则摘要是"引用 + 摘要"而非全文展开。**核心原则**：宏观业务逻辑（规则/权限等）上提至全局知识库。交互说明中仅做规则引用，不在页面说明中重复展开全文。新生成的全局规则需沉淀至企业/项目级独立知识库，并在当前迭代的规则摘要中以列表形式汇总引用。

**规则摘要内容**：

| 分类 | 字段 | 说明 |
| ---- | ---- | ---- |
| 全局规则 | 规则编号 + 定义摘要 | 如"所有配置名称全局唯一" |
| 业务规则 | BR-XXX + 定义与约束摘要 + 影响范围/研发关注点 | 如"BR-Promo-01：满减互斥规则，影响结算页价格计算逻辑" |
| 数据字典 | DD-XXX + 定义与约束摘要 + 影响范围 | 如"DD-Order-Status：订单状态机，影响所有展示订单状态的列表页" |
| 权限控制 | NFR-Auth-XX + 定义与约束摘要 + 影响范围 | 如"NFR-Auth-01：RBAC + 行级数据权限，影响所有列表查询接口" |
| 安全审计 | NFR-Sec-XX + 定义与约束摘要 + 影响范围 | 如"NFR-Sec-02：敏感操作留痕，影响删除/导出接口" |
| 异常兜底规则 | 异常场景 + 兜底策略 + 提示文案 | 如"网络异常：保留表单内容，提示重试" |

**规则来源**：规则的素材来源是 Feature 文档中的业务规则字段和角色权限字段。subagent 从中提取规则编号和摘要，不重复展开全文。

**未编号规则处理**：如果发现 Feature 文档中未编号的规则，subagent 为其分配临时编号（如 `BR-TBD-01`）并标注"待产品确认编号"。

---

## 7. 用户确认点

- 展示交互契约（状态机 + 交互规则表 + 错误提示）+ 规则摘要
- 给出理解回执（覆盖的核心交互数、异常分支数、规则引用数）
- 提出"以上交互规则和异常兜底是否覆盖了全部关键路径？有没有规则过严或过松的？"

## 8. 产出

交互契约（`详细设计/交互契约/<简称>-交互契约.md`）+ 规则摘要（`详细设计/规则摘要/<简称>-规则摘要.md`）。**用户确认后立即步级落盘**：将已确认数据写入 `docs/_extracted/.design/contract-*.json` 和 `rules-*.json`，调用 `render-doc.sh` 渲染到产品库，校验零警告后更新记忆文件。落盘步骤见 `../shared/persist-guide.md` 第 3 节，产出字段见 `../shared/output-contract.md` 第 1.4、1.5 节。

## 9. 质量门

- 核心流程有状态机描述
- 交互规则表包含触发、校验、流转、兜底四列
- 交互规则表的异常兜底列采用 GWT 格式
- 错误提示文案已定义
- 关键 API 调用有约定（如有）
- 异常场景有对应兜底策略；跳过的异常场景已说明理由
- 规则与 Feature/Story 无冲突，以"引用 + 摘要"形式呈现，未重复展开全文
