# 业务流文档写作规范

本文件定义 Step 1 Phase 1 产出的业务流文档（`<简称>-业务流.md`）的文件规范、章节结构和写作标准。

**职责边界**：本文件只管业务流文档的写法。页面映射文档写法见 `page-mapping.md`；HTML 图见 `html-diagram.md`；ID 分配与定稿见 `../shared/persist-guide.md`。

---

## 1. 文件规范

- 路径：产品库 `详细设计/结构与流程图/<简称>-业务流.md`（sourceProduct 直启项目同样写入产品库来源产品目录，无过程项目例外）
- ID：`<简称>-DF-FLOW<nn>`，由 agent 在 Phase 1 写入时分配（分配规则见 `../shared/persist-guide.md` 第 2 节）
- frontmatter：产品库格式，`type: 业务流`

```yaml
---
id: "<简称>-DF-FLOW<nn>"
product: "<产品全名>"
type: "业务流"
aliases:
  - "<产品全名> 业务流"
tags:
  - "<简称>"
  - "业务流"
---
```

## 2. 章节结构

```markdown
# 业务流

## 核心页面层级
（页面层级结构：一级导航 > 二级页面，用加粗领条或表格）

## 系统边界
- **包含**：……
- **不包含**：……（写明排除原因）

## 业务动线
（按功能线组织：每条功能线一个三级标题，头部标注优先级与覆盖 Story，线内分步描述）

## 业务流程图
（Mermaid flowchart；Phase 3 确认后追加流程图 HTML 引用）
```

## 3. 各章节写作规范

### 3.1 核心页面层级

写清一级导航分组和二级页面清单，体现页面在系统中的位置。

| | 写法 | 评价 |
| --- | --- | --- |
| 好 | `- **设备管理**（一级导航）：设备台账、领用申请、归还登记` | 一级分组具体，二级页面可区分功能 |
| 差 | `- 设备相关页面` | 无层级、无页面清单，无法指导导航配置 |

### 3.2 系统边界

包含和不包含都必须写，不包含要带排除原因。

| | 写法 | 评价 |
| --- | --- | --- |
| 好 | `- **不包含**：物流追踪模块（本期 Story 未覆盖，留待后续迭代）` | 明确排除项及原因，边界可追溯 |
| 差 | `- 不包含一些外部模块` | "一些"无指向，边界模糊 |

### 3.3 业务动线（按功能线组织）

业务动线按**功能线**组织。功能线 = 一组 Story 落到软件后形成的一条端到端业务路径（如"建址与审核""质量治理"）。**内容完整性在 md 源头保证**：有几条端到端路径就写几条功能线，下游 HTML 图只做可视化、不做裁剪。

每条功能线一个三级标题，头部标注三要素（线名、优先级、覆盖 Story），线内步骤分步描述：

```markdown
### 功能线一：建址与审核（P0，覆盖 F001-S01~S05）

- **新建地址发起**：地址管理员在【地址库】点击"新建地址"，打开【地址创建表单】
- **审核处理**：进入【审核中心】查看待审核队列，通过或驳回
```

| 规则 | 要求 | 违反后果 |
| --- | --- | --- |
| 功能线头部三要素 | 线名、优先级（P0/P1/P2）、覆盖 Story（列全 Story ID，允许范围写法如 F001-S06~S11） | Story 覆盖无从核对，下游 HTML 无法标注 |
| 禁止合并功能线 | 不为控制篇幅把多条线压缩成一条"主干"；API/组件/后台服务承载的 Story 同样归入对应功能线 | 内容在源头丢失，HTML 图被迫画成单线 |
| Story 全覆盖 | 全部功能线的 Story 并集 = 全部 User Story；发现无功能线承载的 Story 时先向用户确认归属，不得静默遗漏 | 部分 Story 变成"无功能归属"需求，追溯链断裂 |
| 步骤分步描述 | 每步用加粗关键词领条，页面跳转目标用【】标注 | 动线无法逐步还原到页面 |

| | 写法 | 评价 |
| --- | --- | --- |
| 好 | `### 功能线三：质量治理（P0，覆盖 F002-S01~S07）` + 分步描述 | 线名、优先级、Story 覆盖齐全，可直接核对 |
| 差 | `### 走查路径二：日常维护`（无优先级、无 Story 标注） | 无法回答"这条线承载哪些 Story" |

### 3.4 业务流程图

Phase 1 写入 Mermaid flowchart（纯用户操作与页面动线，不涉及底层技术实现），**每条功能线一个 subgraph，subgraph 标题带线名与 Story 范围**，与业务动线章节的功能线一一对应；Phase 3 定稿时在 Mermaid 下方追加 HTML 引用：

```markdown
> 精美交互版见同目录 `<简称>-业务流程图.html`
```

## 4. 与页面映射文档的边界

| 内容 | 归属文档 |
| --- | --- |
| 核心页面层级、系统边界、主干业务动线、业务流程图（Mermaid + HTML 引用） | 业务流文档 |
| Story 到页面的映射表、跳转闭环检查、功能架构图引用 | 页面映射文档 |

业务流文档回答"系统怎么跑"；页面映射文档回答"故事落在哪些页面"。两份文档页面名称必须一致，不一致以用户最新确认的文件为准并同步另一份。
