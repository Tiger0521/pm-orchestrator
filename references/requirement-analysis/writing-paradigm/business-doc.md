# 业务文档写作范式

> 前置读取：本文件与 `templates/business-doc.md` 配套。写业务文档草稿前先读模板，再按本文件规范撰写。
>
> **定位**：业务文档是承载 4 个业务字段（业务价值、业务场景、业务流程、业务规则）的持续更新文档。**不按能力划分章节**；能力只作为业务场景表、业务规则表每一行的「所属能力」列存在。它是 User Story 阶段用户旅程提取的唯一输入、业务规则维护的唯一载体（业务规则是拆故事时 GWT 生成与边界异常映射的输入）。**持续更新，不随串行环节结束。**

---

## 扁平 4 字段结构

业务文档直接由 4 个业务字段（二级章节）组成，各能力不再单独成节；能力的业务内容以行级「所属能力」列落进业务场景表、业务规则表：

```text
# {{产品名}} 业务文档
## 业务价值
## 业务场景
## 业务流程
## 业务规则
## 变更记录
```

- 字段顺序固定为 业务价值 → 业务场景 → 业务流程 → 业务规则 → 变更记录。
- 能力信息只出现在场景表、规则表的「所属能力」列；不在 4 个字段下按能力再分子节。
- 整体架构级的整体业务规则记录在架构设计文档中，不写入业务文档。

## 4 个业务字段写作规范

### 业务价值（稳定字段）

- **产品级一段**，一句话说清产品整体对用户和业务的价值，附价值类型标注（效率/营收/体验/合规）。
- 至少 1 条说明"不做会损失什么"。
- **业务价值是不怎么变的**：只在产品定位、范围或战略调整时才重构本字段；日常迭代新增能力、新增场景/规则不修改业务价值。

### 业务场景（旅程提取唯一输入）

- 表格承载：场景编号 / 场景名称 / **所属能力** / 参与角色 / 触发条件 / 用户目标。
- 场景编号 `SC-XX` 产品内唯一、持续累加，不随内容修改重排。
- 「所属能力」列填该场景所属的能力名，与产品库 Feature 能力名一致；是旅程提取按能力分组推导能力内旅程节点的依据。
- 场景描述写"用户从什么状态开始，经过什么动作，到什么结果"，不写系统操作步骤。
- 该表是用户故事阶段旅程提取的唯一输入。

### 业务流程

- **产品级多条主线流程**，每条流程一个子节（`### 流程一：{{名称}}`），按 `FL-XX` 编号（产品内唯一、持续累加，不按能力重排）。
- 每个流程写触发条件、操作角色、系统行为、输出结果；异常分支和兜底策略用分条补充。
- 同一流程若覆盖多个能力，在流程描述中说明涉及的场景（SC-XX）即可，不按能力拆成多条重复流程。

### 业务规则（易变字段）

- 表格承载：规则编号 / 规则说明 / **所属能力** / 适用范围 / 异常处理。
- 规则编号 `BR-XX` 产品内唯一、持续累加。
- 「所属能力」列填该规则所属的能力名，与产品库 Feature 能力名一致；是 story-map 阶段 GWT 生成与边界异常映射按 Feature 取规则的依据。
- 异常处理列不能为空，写"如果规则被违反，系统怎么处理"。
- **业务规则是会变化的**：规则是业务文档最活跃的字段，随业务演进新增、修订或废弃；日常迭代的更新主要发生在本字段。

## 更新规范

业务文档采用**有添加就直接重构**的整体重写方式（不覆盖已确认内容，而是以产品库现有版本为基线并入新增后整体重写）：

| 时机 | 动作 |
| --- | --- |
| 首次拆能力（Feature draft） | 追问 4 个业务字段时收集到 `business-doc-draft.md`（业务价值在首个能力确认时一并收齐，之后保持稳定），Feature persist 时向用户展示完整业务文档草稿，确认后落盘 |
| 每次拆能力/迭代新增 | 把新增业务内容并入草稿对应字段（新增场景/规则行标注所属能力），persist 时以产品库现有文档为基线、并入新增内容后**整体重写** 4 个字段，不按能力名增量打补丁 |
| 拆故事前 | 检查 `lastUpdated` 与最新 Feature persist 时间差，不满足则提醒更新 |

- **业务价值**：默认保留产品库现有版本，不随迭代重写；产品定位调整时才重构，并在变更记录说明。
- **业务场景 / 业务流程 / 业务规则**：按新增内容并入，场景/规则编号从产品库现有文档取最大序号继续累加，不重排。
- 每次更新后：更新 frontmatter `lastUpdated`；在「变更记录」表追加一行（日期 / 变更内容 / 变更人）。

## 追溯与引用

- Feature 通过 wikilink 关联整个业务文档：`[[{{产品简称}}-业务文档]]`；不再指向能力章节，Feature 的对应业务内容靠场景/规则表的「所属能力」列定位。
- `refs.json` 注册 `business-doc` 节点，edges 记录 `Feature ──references──▶ 业务文档`。
