# 用户故事地图写作规范

## 1. 核心原则

### 1.1 地图优先，列表其次

用户故事地图的核心形态是**二维网格**，不是一维列表。所有输出必须以 2D 矩阵表格为主体，故事卡片详情是矩阵的补充而非替代。

### 1.2 禁止 ASCII 画图

不使用 ASCII 字符画（如 `├─`、`──>`、`[条件?]`）画流程图。旅程叙事线通过以下方式体现：
- 矩阵列标题按旅程阶段从左到右排列
- 旅程叙事线章节的文字描述
- 行走路径叙事中的顺序描述

### 1.3 表格为王

所有结构化信息优先使用 Markdown 表格呈现：
- 2D 故事地图矩阵 = 表格
- 能力覆盖矩阵 = 表格
- 跨能力关联 = 表格
- MVP 范围统计 = 列表或表格

## 2. 2D 矩阵表格写法

### 2.1 表头结构

总览矩阵表头：

```markdown
| 优先级 | {阶段1} | {阶段2} | {阶段3} | {阶段4} | {阶段5} |
| --- | --- | --- | --- | --- | --- |
```

能力级矩阵表头：

```markdown
| 优先级 | {节点1} | {节点2} | {节点3} | {节点4} | {节点5} |
| --- | --- | --- | --- | --- | --- |
```

### 2.2 行顺序

行按优先级从上到下：
1. **P0 MVP核心**（最上行）
2. **P1 体验增强**（中间行）
3. **P2 运营支持**（最下行）

行标题使用加粗：`**P0 MVP核心**`

### 2.3 单元格内容格式

#### 总览矩阵（紧凑形式）

每条故事占一块，多条故事之间用 `<br>` 分隔：

```markdown
⭐[[故事文件名|故事简称]]<br>角色：{角色}
```

非 P0 故事不加 ⭐。

#### 能力级矩阵（完整形式）

```markdown
⭐[[故事文件名|故事简称]]<br>角色：{角色}<br>价值：{核心价值}
```

### 2.4 空单元格

空单元格统一标注 `-`，不使用"无""空""N/A"等其他写法。

### 2.5 表格注释

表格后使用引用块（`>`）添加说明：
- ⭐ 标记的含义
- 空单元格的含义
- 其他需要说明的约定

## 3. 行走路径标注规范

### 3.1 ⭐ 标记

- ⭐ 标记在故事标题前，表示该故事是 MVP 行走路径故事。
- 只有 P0 故事可以被标记 ⭐。
- 不是所有 P0 故事都加 ⭐，只有行走路径上的核心故事加 ⭐。
- 如果一个旅程阶段有多条 P0 故事，选择最核心的 1-2 条加 ⭐。

### 3.2 行走路径叙事

行走路径叙事使用以下格式：

```
**行走路径**：用户通过 [⭐{故事简称}] 完成{目标}，通过 [⭐{故事简称}] 完成{目标}，...
```

要求：
- 按旅程阶段顺序从左到右描述。
- 每个阶段至少提及一条行走路径故事。
- 使用"通过...完成..."句式。
- 不机械拼接故事标题，融入叙事语境。

## 4. wikilink 规范

### 4.1 格式

```markdown
[[文件名（不含.md）|显示名]]
```

- 文件名：产品库中实际的故事文件名，不含 `.md` 后缀和路径前缀。
- 显示名：简短别名，不超过 8 个字。
- 如果文件名本身就很短，可以省略显示名：`[[文件名]]`

### 4.2 文件名映射

- wikilink 必须指向产品库中实际存在的文件。
- 如果引用的故事文件不存在（规划中的故事），不加 wikilink，标注为"规划中"。
- 如果产品库中的文件名与故事地图中的引用名不一致，以产品库实际文件名为准。

## 5. 章节标题规范

| 章节 | 标题级别 | 标题文本 |
| --- | --- | --- |
| 文件标题 | `#` | `{产品名} 用户故事地图 总览` 或 `{产品名}-{能力名}-用户故事地图` |
| 产品概述 | `##` | `产品概述` |
| 旅程叙事线 | `##` | `全局用户旅程叙事线` 或 `用户旅程叙事线` |
| 能力覆盖矩阵 | `##` | `能力覆盖矩阵` |
| 2D 矩阵 | `##` | `故事地图矩阵` |
| 行走路径 | `##` | `MVP 行走路径` 或 `能力级行走路径` |
| 跨能力关联 | `##` | `跨能力关联` |
| 能力索引 | `##` | `能力索引` |
| 故事卡片详情 | `##` | `故事卡片详情` |
| 故事卡片子标题 | `###` | `P0 - MVP核心` / `P1 - 体验增强` / `P2 - 运营支持` |
| 单条故事标题 | `####` | `⭐ {故事标题}` 或 `{故事标题}` |
| 返回总览 | `##` | `返回总览` |

## 6. frontmatter 规范

```yaml
---
product: "{产品名}"
type: "指南"
capability: "{能力名}"  # 仅能力级地图有此字段
tags:
  - 用户故事地图
  - "{能力名或总览}"  # 能力级地图加能力名，总览加"总览"
title: "{完整标题}"
---
```

- 所有字段值用双引号包裹。
- `type` 统一为 `"指南"`。
- `tags` 至少包含 `"用户故事地图"`。

## 7. 数据一致性维护

### 7.1 总览与分文档一致

- 总览地图的故事总数 = 各能力级地图故事总数之和。
- 总览索引表中的能力列表 = 实际能力级地图文件列表。
- 总览矩阵中的故事与能力级矩阵中的故事一一对应。

### 7.2 不重复维护

- 总览地图不复制各能力的故事详情，只索引（wikilink）。
- 故事卡片详情只在能力级地图中展开。
- MVP 切面只在总览地图中呈现，不在能力级地图中重复。

### 7.3 覆盖空白显式标注

- 矩阵中的空单元格标注 `-`。
- P0 行的空单元格额外标注 **行走路径断裂**。
- 覆盖空白清单在总览地图末尾列出（如有）。
