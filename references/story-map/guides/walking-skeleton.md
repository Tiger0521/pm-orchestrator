# MVP 行走路径识别指南

## 1. 行走路径定义

行走路径（Walking Skeleton）是用户故事地图最上层（P0）从左到右的一条连贯路径，代表用户完成核心业务目标所需的最小故事集合。

行走路径是 Jeff Patton 用户故事地图的核心概念：它不是所有 P0 故事的简单集合，而是**在旅程横轴上从起点到终点的最短连贯路径**。

## 2. 识别步骤

### 2.1 检查 P0 覆盖

1. 在每个能力级矩阵的 P0 行中，检查每个旅程节点是否至少有一条 P0 故事。
2. 记录覆盖情况：

| 旅程节点 | P0 故事数 | 状态 |
| --- | --- | --- |
| 智能补全 | 3 | 覆盖 |
| 手工录入 | 2 | 覆盖 |
| 查重校验 | 2 | 覆盖 |
| 审核核准 | 0 | **断裂** |
| 消歧核准 | 1 | 覆盖 |

### 2.2 处理路径断裂

如果某个旅程节点没有 P0 故事：

1. **检查是否有 P1 故事可以提升**：该节点是否有 P1 故事可以提升为 P0？如果可以，建议提升并标注为"建议提升"。
2. **检查该节点是否需要 MVP 覆盖**：有些节点可能确实不需要 MVP 覆盖（如"运址"类运营节点在 MVP 阶段可能只需要基础看板）。如果不需要，标注为"该节点无需 MVP 覆盖"。
3. **向用户确认**：展示断裂情况和处理建议，让用户决定。

### 2.3 标记行走路径故事

在矩阵中标记行走路径上的 P0 故事：

- 在能力级矩阵中，行走路径故事用 ⭐ 标注。
- 如果某个节点有多条 P0 故事，选择最核心的一条作为行走路径故事（其他 P0 故事不加 ⭐ 但仍在 P0 行）。
- 选择标准：最接近"端到端完成该节点目标"的故事。

### 2.4 撰写行走路径叙事

用一段连贯的叙事描述行走路径，格式：

```
用户通过 [⭐手工录入] 完成地址创建，通过 [⭐自动查重] 校验地址唯一性，
通过 [⭐分级审核] 确认地址质量，通过 [⭐消歧核准] 解决重名冲突。
```

叙事要求：
- 从能力内旅程起点到终点，按顺序描述。
- 每个旅程节点至少提及一条行走路径故事。
- 使用"通过...完成..."句式，强调用户动作和业务结果。
- 不机械拼接故事标题，而是融入叙事语境。

## 3. MVP 范围统计

### 3.1 统计项

| 统计项 | 说明 |
| --- | --- |
| P0 故事总数 | 全部 P0 故事的数量（含非行走路径的 P0） |
| 行走路径故事数 | 标注 ⭐ 的 P0 故事数量 |
| 覆盖旅程节点数 | P0 故事覆盖的旅程节点数量 / 总节点数 |
| 覆盖率 | P0 故事数 / 全部故事数 × 100% |

### 3.2 统计示例

```
**MVP 范围**：
- P0 故事：27 条（其中行走路径 12 条）
- 节点覆盖：5/5 节点（100%）
- 故事覆盖率：27/77 = 35%
```

## 4. 行走路径验证

### 4.1 连贯性验证

行走路径叙事写完后，验证：
- 从能力内旅程起点到终点，是否有逻辑断裂？
- 前一个阶段的输出是否能支撑后一个阶段的输入？
- 用户是否能通过行走路径完成核心业务目标？

### 4.2 完整性验证

- 行走路径是否覆盖了设计文档中定义的全部核心场景？
- 是否有核心场景在行走路径中缺失？

### 4.3 可行性验证

- 行走路径上的故事是否都是可独立交付的？
- 是否有故事之间存在硬依赖，导致无法独立交付？

如果验证不通过，调整行走路径故事选择或向用户报告问题。

## 5. 能力级行走路径

每个能力级地图都有自己的行走路径：

- 能力级行走路径是该能力的 P0 故事在能力内旅程节点上的连贯路径。
- 能力级行走路径故事在能力级矩阵中也用 ⭐ 标注。
- 能力级行走路径叙事描述用户在该能力内完成核心目标的路径。

能力级行走路径示例：
```
建址能力行走路径：用户通过 [⭐手工新建] 录入地址，通过 [⭐批量导入] 批量建址，
通过 [⭐审核] 确认地址质量，通过 [⭐消歧核准] 解决重名冲突。
```
