# 用户故事地图落盘指南

## 1. 前置条件

- `mode=persist` 且用户已明确确认某个能力地图（或总览）的草稿。
- `userContext` 中包含用户确认信号和确认的 `target`（能力名或 `overview`）。
- `outputTargets` 已明确指向产品库的 `用户故事地图/` 目录。

## 2. 落盘步骤

### 2.1 确认落盘目标

根据 `userContext` 中的 `target` 确定本次落盘的文件：
- `target=capability-{能力名}` -> 落盘该能力的地图文件。
- `target=overview` -> 落盘总览文件。

**每次只落盘一个文件**，不批量落盘。

### 2.2 确认输出目录

确认 `outputTargets` 中的目录路径在产品库范围内。如果产品库中没有 `用户故事地图/` 目录，创建该目录。

### 2.3 写入文件

按 `output-contract.md` 的结构和对应模板写入文件：

- 能力地图：`{产品名}-{能力名}能力-用户故事地图.md`
- 总览地图：`{产品名}-用户故事地图-总览.md`

### 2.4 校验 wikilink

落盘后校验：
- 能力地图中的故事 wikilink 指向的用户故事文件在产品库中存在。
- 总览地图中的能力索引 wikilink 指向的能力级地图文件已创建。
- 如果存在链接不匹配，修正链接为实际文件名。

## 3. 落盘规则

- 只写入用户已确认的内容，不得重新生成、改写、压缩或扩写。
- 文件编码使用 UTF-8。
- 换行符使用 LF。
- frontmatter 中的字段值使用双引号包裹。
- wikilink 使用 `[[文件名|显示名]]` 格式，文件名不含 `.md` 后缀。

## 4. 覆盖已有文件

如果产品库的 `用户故事地图/` 目录中已存在同名文件：
- 向用户确认是否覆盖。
- 确认覆盖后写入新文件。
- 不保留旧文件备份（由用户自行管理版本控制）。

## 5. 落盘后汇报

落盘完成后，向主调度器返回 `status=map-persisted`，并在回执中包含：

- `target`：本次落盘的目标（`capability-{能力名}` 或 `overview`）
- 已写入的文件名
- 该文件中的故事数量
- 如果是能力地图：行走路径故事数
- 如果是总览：汇总的全部能力地图数和总故事数
- 下一步提示：如果还有未处理的能力，提示"下一个能力是 {能力名}"；如果全部能力完成，提示"接下来生成总览"；如果总览完成，提示"全部地图已完成"
